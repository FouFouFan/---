# 五子棋联机对战游戏 — 需求规格说明书 (spec.md)

## 1. 项目概述
开发一个支持两名玩家实时联机对战的五子棋游戏。采用客户端/服务器（C/S）架构：
- 服务端：负责房间匹配、棋盘状态同步、胜负判定、超时判定。
- 客户端：提供 15x15 棋盘界面、黑白棋子显示、落子交互、计时显示。

## 2. 术语定义
- **棋盘**：15x15 网格，交叉点落子，坐标 (row, col)，范围 0–14。
- **黑棋**：先手方。
- **白棋**：后手方。
- **回合**：当前允许落子的一方。
- **超时**：某一方在其回合内超过 5 分钟未落子。

## 3. 功能需求

### 3.1 服务端 (Server)
| 编号 | 需求 | 说明 |
|------|------|------|
| S-01 | 房间匹配 | 玩家进入匹配队列，凑齐 2 人即创建房间并分配黑白方（先到者为黑或随机） |
| S-02 | 棋盘状态维护 | 服务端保存权威棋盘状态（15x15 二维数组） |
| S-03 | 落子校验 | 校验落子合法性：坐标在范围内、该点为空、为当前回合方落子 |
| S-04 | 状态同步 | 每次合法落子后，将落子信息广播给房间内两个客户端 |
| S-05 | 胜负判定 | 每次落子后检测横、竖、两条对角线是否形成连续 5 子 |
| S-06 | 超时判定 | 每个回合开始启动 5 分钟倒计时，超时则判该方失败 |
| S-07 | 对局结束处理 | 广播游戏结束消息（胜者、原因：五连/超时/认输可选） |
| S-08 | 断线处理 | 一方断线时通知另一方，对局终止（断线方判负） |

### 3.2 客户端 (Client)
| 编号 | 需求 | 说明 |
|------|------|------|
| C-01 | 棋盘渲染 | 绘制 15x15 棋盘网格与星位 |
| C-02 | 棋子渲染 | 黑白棋子显示在交叉点上 |
| C-03 | 落子交互 | 玩家点击交叉点发起落子请求，仅在自己回合可操作 |
| C-04 | 状态同步展示 | 接收服务端广播并更新本地棋盘 |
| C-05 | 回合提示 | 显示当前轮到哪一方 |
| C-06 | 倒计时显示 | 显示当前回合剩余时间（5 分钟倒计时） |
| C-07 | 结果提示 | 对局结束弹出胜负结果 |
| C-08 | 匹配界面 | 提供"开始匹配"入口与等待提示 |

### 3.3 非功能需求
- **实时性**：落子同步延迟应低于 500ms（局域网/本机环境）。
- **一致性**：以服务端棋盘状态为唯一权威来源，客户端不自行判定胜负。
- **无悔棋**：不提供悔棋功能。
- **并发**：服务端需支持至少 1 个房间（2 客户端）同时在线，架构可扩展至多房间。

## 4. 通信协议（建议）
- 传输：WebSocket（推荐）或 TCP Socket。
- 消息格式：JSON。
- 主要消息类型：
  - `match_request` / `match_success`（含分配颜色）
  - `move`（row, col, color）
  - `move_rejected`（原因）
  - `game_state`（棋盘快照）
  - `turn_start`（含剩余时间/截止时间戳）
  - `game_over`（winner, reason）
  - `opponent_disconnected`

## 5. 约束与假设
- 棋盘固定 15x15，无禁手规则（自由五子棋）。
- 时间限制固定 5 分钟/回合，不可配置（可作为可选扩展）。
- 不支持观战、聊天、悔棋。
- 单局结束后玩家可返回匹配。

## 6. 技术栈建议（不限）
- 服务端：Node.js + ws / Python + websockets / Java Netty 等。
- 客户端：Web（HTML/Canvas 或 React）、桌面（Electron/PyQt）均可。
