# SDD 规范文档处理流程（项目规则）

> 适用场景：用户提供 `spec.md` / `task.md` / `checklist.md` 三份 SDD 规范文档时
> 级别：必须遵守

## 流程

1. **完整阅读** — 用 Read 工具逐字读完三份文档，不得跳读或凭记忆推断。
2. **复述确认** — 用 3-5 句话向用户复述「项目目标、技术栈、开发顺序」并说明执行纪律。**必须等用户明确确认后**才能开始任何任务。
3. **单任务串行执行** — 严格按 task.md 顺序，每次只执行一个任务（从第一个未完成的开始），不得超前。
4. **任务内自检** — 每完成一个任务，对照 checklist.md 对应条目自检，并报告：
   - 本次创建/修改了哪些文件
   - 对应 task.md 的哪一条（ID + 标题）
   - checklist.md 中哪些项已通过、哪些未通过
   - **具体验证路径**：用户如何手动验证本次产出（访问哪个 URL / 执行哪个命令 / 打开哪个页面 / 观察什么现象），必须具体到可操作步骤，不能只说"请验证"
5. **停下等验证** — 写完代码后立即停下，等用户验证确认后才进入下一个任务。
6. **不主动创建文档类文件**（除非任务明确要求），不修改与当前任务无关的代码。
